## The README's job

The README is the repo's landing page and already does its work well. Division of labor:

- **The opening paragraph carries the identity** (worry-first, the promise stated plainly). It derives from IDENTITY/MESSAGING — when identity changes, that paragraph is where it lands.
- **"One week, run twice" stays the proof.** It is the repo's strongest asset and the messaging's proof section (MESSAGING §channel angles).
- **The rest of the README belongs to engineering**, not PR: layers, build order, status, agent instructions. PR never reaches below the fold.
- **The repo's reader is a builder, not a customer.** The spec-not-app disclaimer stays at the very top — it reads as honesty to an engineer and as "nothing for me here" to a tutor, and that's correct routing: non-technical readers are the landing page's job, not the README's.

## Standing rules

- **The repo never oversells its state.** "Design complete, implementation not started" is stated in the opening blockquote and stays there until it stops being true. The honest state *is* the pitch (MESSAGING §objections).
- **No commercial language on the facade.** Pricing, payment, revenue, and money mechanics do not appear in the README or any outward copy (VOICE §Commercial silence).
- No badges beyond factual ones (license). No star-count furniture, no "roadmap" theater.
- Release notes, if any, are plain records of what became true — they double as the landing page's State 1 progress stills (LANDING §state 1).
