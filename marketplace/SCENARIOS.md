## F — Formats (the closed grammar)
- **F1 [no programs]** A bundle containing an executable-shaped payload (script string, event-handler, lifecycle hook) is **unrepresentable in the meta-schema** — it fails validation before the install door is ever reached. **The probe runs nested, and it runs on node type as well as payload** *(2026-09-12)*: an executable-shaped prop buried in a `group` → `row` → field chain fails exactly as a top-level one does, and a schema naming a node type **outside the active v1 manifest** is unrepresentable the same way — `file-slot` named, anywhere in the tree, in `domain` or in a `shared_shapes[].form` (`SPEC.md §1.2`'s file-slot clause; `../app/SPEC.md §4.1`; `../security/SPEC.md §4`). No accept-list-only variant, fallback attachment control or direct submission is admitted in its place. A `signature` node in the same form still validates — in-form consent is not an upload.
- **F2 [off-menu rule refused]** A bundle carrying a rule shape not on the engine's closed menu is refused with the failing entry named — never stored, never a runtime path.
- **F3 [no people]** A bundle attempting to carry a counterparty, booking, history or personal-data record cannot express it: the fields do not exist. Asserted as schema-level unrepresentability, not as a runtime strip. A private configured-definition payload or a named private default substituted for the publication projection is rejected as outside the bundle grammar; no per-use participant, contact, credential or live Grant is selectable (`SPEC.md §§1.2/2`). The existing publisher-reviewed field-name residual is stated honestly, not claimed mechanically absent. **Nested carrier probes, over the transferable subset** (`SPEC.md §1.2`) *(2026-09-12 — every probe here tested the bundle's top-level fields, and the personal value that actually fitted through the grammar sat inside a schema node)*: a `text-input` whose `default?` holds a synthetic contact string, a node whose `props` carry a prefilled address or an option naming a person, and a `bind` resolving to a board, account, party, contact, token or artifact reference are each outside the subset and each unrepresentable — asserted at the top level **and again inside a `group` → `row` → field chain**, so nesting is no escape. Run the same probes over one schema in its **draft, finalized, saved and listed** forms: a document legal in one of those and illegal in another falsifies the subset. The legal cases must still pass in every one of them — blank **rule-operand parameters**, neutral structure, and permitted publisher-choice rule operands including a whole duration range with its optional step/anchor. A subset that refuses the legal case is as wrong as one that admits the illegal.
- **F4 [span floor]** The **"Free Time Available"** seed validates: one shared bookable-availability shape with blanked hours/duration/buffer. *(A: Sofia's outward slice, generalized.)* Also validate the duration carrier as the existing typed range, as range with step/anchor, and as the whole-operand `blanked` sentinel. Refuse malformed aggregates rather than silently discarding step/anchor (`SPEC.md §1.2`; engine §3).
- **F5 [span ceiling]** The **dive-center** seed validates: multi-resource shapes (instructor roster slots, boat, pool, gear), course kinds, governed rules with blanked operands. *(C: Hug Ocean's setup, generalized.)* **Unblocked 2026-08-06** — boat min-pax is now the engine's `min-occupancy` menu entry (`../engine/SPEC.md §3`), and the multi-day course shape is `KindTemplate` (`§1.12`). The seed is constructible.

## P — Publish
- **P1 [unpublish is safe]** Given an installed copy, when the upstream is unpublished or re-versioned, the installed copy is **byte-identical** afterward — fork isolation.
- **P2 [owner-publish — the umbrella]** A signed-in owner publishes a **saved** bundle: the listing appears in the public catalog, carrying detailed information on what it is and what it does (listing copy required); another account can install it. Unsigned / unauthenticated publish is refused. **Verified in two halves, P2a and P2b** *(split 2026-08-29 — the one row was gated at three build steps while its verb half and its install half become executable at different ones; the row stays defined as the umbrella both halves report to)*. *(FD-82. Replaces the former absence test that forbade any user surface.)*
- **P2a [publish — the verb half]** `catalog.publish` from a **signed-in owner credential** against the service mock succeeds, and the listing appears in `catalog.list`; an unsigned or unauthenticated publish is refused. *(`SPEC.md` §2 + `INTERFACES.md` §1.)* **Assert the caller and the credential, not only the outcome** *(2026-09-12)*: the call is the **app marketplace adapter's**, made on an **explicit owner act** and carrying that owner's **current** session credential (`INTERFACES.md §2`). An unsigned call, a stale or absent credential, and **another owner's** credential each refuse; `catalog.unpublish` over the same mock stays bound to the listing's own publisher, which is P5a's law cited rather than restated.
- **P2b [publish — the install half]** The published listing carries its **listing copy**, and a second account installs it. *(`SPEC.md` §2.)*
- **P3 [save is not publish]** Saving a bundle for the owner does not list it. Catalog listing happens only when they press publish. Under `SPEC.md §§2–3`, start with both catalog and saved set empty. A successful no-match lookup permits neutral from-scratch authoring; an unavailable lookup reports unavailable, never invents a match or emptiness, and permits retry or user-chosen authoring. Save chosen duration 30–120 minutes with step 15/anchor 30, 09:00–23:00 windows, both five-minute buffers and an explicitly blank meeting link; reload on another signed-in device and compare the retained typed values, scope, pins and explicit answers. A supplied valid hourly-price/reminder configuration is retained as configuration, never computed in the app or cloned as live authority. Save opens a fresh unbooked use with blank participant/contact fields; an Arthur use followed by a Bobby use cannot carry over their values or credentials. No booking, token mint, send or catalog call occurs on save/open. An incomplete saved draft shows unresolved fields and disabled policy, never successful eligibility. Replace advances the same definition only on success; Save as new yields a separate 45-minute identity/use while the original range, links and bookings remain unchanged. A per-use date or Student edit and draft-row removal never ask Replace/Save as new. Exercise triggered named-default clarification in definition-edit context and an explicit retained private value, plus ordinary reuse and already-answered controls; the private value survives reload/copy by explicit scope but never publication. Finally explicitly publish the separate data-free projection against the mock, then install from another account; private operands not separately selected as publisher choices are blanked, and duration step/anchor is either preserved whole as an authorized choice or blanked whole. Names, activities and prices are fixture values, never routing conditions. Run the same document operations without rendering. A second account cannot enumerate/read/revise/remove or recover the first account’s write; refusal reveals no existence. Two simultaneous replacements from one revision yield one persisted successor and one conflict, never overwrite. Drop the save acknowledgement after persistence, reload and retry the same write id: recover one definition revision and its original fresh-use identity. A different payload under that id refuses. A known validation refusal shows unsaved, an outstanding write pending, a lost outcome unknown, and only read-back persistence saved. Keep current settings while a blocked replacement is resumed with its branch choice; final compatibility/admission and the composed story remain their named BUILD proofs. **Assert the separation at the call itself** *(2026-09-12)*: across the whole walk, the save and every storefront, gallery and preview render make **zero** `catalog.publish` calls against the mock — an absence asserted on the recorded calls, not on the catalog's contents — and the one publish that does occur is the explicit owner act, carrying only the saved revision's data-free projection through the named adapter (`INTERFACES.md §2`).
- **P4 [no extract]** Asking to publish a **populated** board (counterparties, bookings, records) is refused. The agent names the lawful path: author / save-as-bundle (blanked shape), then publish that. *(Engine no-export; `SPEC.md` §2.)* **Assert it at the adapter too** *(2026-09-12)*: the refused act reaches **no** `catalog.publish` call at all, and across every body that does cross the seam in this run no private populated record — a participant, a contact, a credential, a live Grant, a named private default — appears (`INTERFACES.md §2`; the security mirror is `../security/SCENARIOS.md` M2).
- **P5a [unpublish — the verb half, good-agnostic]** `catalog.unpublish` removes the item from `catalog.list` for **either good**; a caller who is not the listing's own publisher is refused. *(`SPEC.md` §2's unpublish law + `INTERFACES.md` §1's verb note.)*
- **P5b [an unpublished template stops being installable]** After unpublish the template can no longer be installed, and the copy installed before it is **byte-identical** — P1's law, cited rather than restated. *(`SPEC.md` §2.)*
- **P5c [unpublish never reaches an entitled skin]** *Given* an entitled account with a store skin installed and its pack persisted on-device, *when* that listing is unpublished, *then* the **entitlement and the on-device pack copy are both unaffected** — the skin-side mirror of P1. Unpublish is a **catalog** event; this row asserts nothing about an entitlement event, which is a different thing entirely (`SPEC.md` §4's non-collision note). *(`SPEC.md` §3's skin bullet.)*
- **P6 [deleting a saved bundle]** An owner deletes a saved bundle: it is removed, and a listing already published from it is unaffected. *(`SPEC.md` §2's delete-saved.)* Exercise `SPEC.md §2` retirement first with S13b’s unused 45-minute copy: read no links/bookings, disclose its empty use, retire that entry/use and reread the untouched original. Then use live links, a populated draft, an unknown pending booking and a committed lesson as distinct dependencies. Show actual references and chosen effects; keep the definition active until resolutions are known, preserve retained terms/history and perform no hidden link revocation or booking cascade. Insert a new use/link reference between approval and retirement, and race a reserved in-flight use or a booking submission on an already-open empty use: stale retirement refuses without partial cleanup; retry requires the changed set to be reviewed. Retirement winning first prevents a new reference. A committed booking cannot be discarded as an empty use. The published listing and another owner’s installed copy remain byte-identical throughout; unpublish is tested separately.
- **P7 [re-publish lists the newest]** A re-published bundle: the catalog lists the **newest** version, and installs from then on fork that version. *(`SPEC.md` §2's "the catalog lists the newest".)*
- **P8 [a skin publish from an owner credential is refused]** Publishing a **skin** from an owner (non-admin) credential is refused, **with the lawful path named** — the admin pack pipeline. *(`SPEC.md` §0's skins-stay-admin + `../security/SPEC.md §11`'s two-paths-per-good mirror.)*

## I — Install
- **I1 [snapshot fork]** Installing writes a provenance-stamped local copy (`createdVia: install`, source id + version); no live link, no subscription record exists anywhere. Read that fork through the same account-document adapter as private saves (`SPEC.md §3`), scoped to the installer with its own id/revision. The installer’s later configured defaults persist independently of the source projection; publication edits, original retirement and lost-acknowledgement retries cannot change or duplicate this copy.
- **I2 [parameters via propose→confirm]** Installing "Free Time Available", the agent walks each blanked parameter as an ordinary proposal — *their* 30 minutes is their setting — and **nothing writes without confirm**. *(A: Sofia would have installed this instead of authoring from scratch.)*
- **I3 [validated at the door]** A tampered bundle (any F1/F2/F3 violation) is refused **whole**, with the failing entry named — no partial install. **The tampered set includes the `SPEC.md §1.2` subset violations** *(2026-09-12)*: a nested node `default?` value, a value-bearing `props` member, a resolved owner/board/party reference and a `file-slot` node each refuse the **entire** bundle, each naming the failing entry by its node path — never a partial install, and never a silent strip of the offending node in place of a refusal. - **I4 [installs compile to normal writes]** The post-install board state is byte-equivalent **in shape** to the same setup authored by hand through the console. *(C: an installed dive bundle equals the hand-built setup behind Hug Ocean's week.)* **The Given is a lived-in board, not a fresh account** *(2026-09-12 — the row printed post-install shape equivalence and nothing else, while `../user-stories/Situations/Situation-C-prime/README.md` records the 2026-08-07 domain-brief ruling's consequence that "install-into-lived-in-board stays covered at scenario level only" and C′'s run says "the harder lived-in install is carried by scenario I4, not told here" — the coverage was assigned to this row and the row's Given never held it)*: the baseline carries **unrelated confirmed commitments, governing rules the owner set themselves, and a prior installed fork from a different bundle** before the install starts. - **I5 [uninstall keeps the past]** Uninstalling removes the active source document **and any unreferenced `draft` (disabled) rules the walk left**, through their ordinary lifecycle path; every rule and commitment **already confirmed** stands unchanged. *(Aligned 2026-08-29 to `SPEC.md` §3, its home — the row restated "the source document only", which the same section's partial-walk cleanup and I8 both contradict.)* Apply the P6 reference/race controls to an installed fork under `SPEC.md §2`; referenced revisions and active uses are not silently deleted. - **I9 [a newer manifest version refuses whole]** A bundle stamped with a **newer catalog-manifest version than the client's** refuses **whole**, with **both versions named** in the refusal. *(`SPEC.md` §3's door-compare rule.)* **The comparison asserted, not assumed** *(2026-09-12; the printed type and comparator are `../app/SPEC.md §4.1`'s)*: a client at **10** accepts a bundle stamped **2** — *"10 is newer than 2"*, which the string reading gets backwards, so this arm fails a lexicographic implementation — and an **equal** stamp accepts. - **E4 [nothing licensed leaks — content-based]** No licensed derivative is reachable by an unentitled account **in any form**: no long-lived or cross-account-reusable URL, and **no rendition inlined as data** in any unentitled-reachable document (the LQIP data-URI case, FD-31), nor any public artifact (repo, client bundle, cache header that outlives the signature). *(Restated content-based 2026-08-21 — scoped to URLs, this scenario structurally could not see the 24px inlined copy of the photograph being sold.)* **Ranged over every body the seam returns** *(2026-09-12 — "in any form" was content-based and still left which *responses* it was asserted against to the reader, while `INTERFACES.md §1` now prints them)*: assert it on `catalog.list`, on `catalog.get` and on the grant result alike, not only on the asset-delivery call, and assert a signed URL minted for one account **does not serve a second account's request** while it is still live.
- **E5 [withdrawn entitlement deactivates at the next check] `[MUST]`** *Given* an account entitled to a store skin, with that skin **active and in a fave slot** and its pack persisted on-device, *when* the closed service withdraws the entitlement and the next entitlement check occurs (skin activation, or app open), *then* the skin **deactivates**, its **fave slot clears**, and appearance falls back to the shipped four + Plain. - **E6 [offline never revokes] `[MUST]`** *Given* the same withdrawn entitlement, *when* the service is unreachable so no check can complete, *then* the last-known entitlement stands and the skin keeps rendering at full function — no flash, no error wall, no outage-triggered downgrade.
