## F — Formats (the closed grammar)
- **F1 [no programs]** A bundle containing an executable-shaped payload (script string, event-handler, lifecycle hook) is **unrepresentable in the meta-schema** — it fails validation before the install door is ever reached.
- **F2 [off-menu rule refused]** A bundle carrying a rule shape not on the engine's closed menu is refused with the failing entry named — never stored, never a runtime path.
- **F3 [no people]** A bundle attempting to carry a counterparty, booking, history or personal-data record cannot express it: the fields do not exist. Asserted as schema-level unrepresentability, not as a runtime strip.
- **F4 [span floor]** The **"Free Time Available"** seed validates: one shared bookable-availability shape with blanked hours/duration/buffer. *(A: Sofia's outward slice, generalized.)*
- **F5 [span ceiling]** The **dive-center** seed validates: multi-resource shapes (instructor roster slots, boat, pool, gear), course kinds, governed rules with blanked operands. *(C: Hug Ocean's setup, generalized.)* **Unblocked 2026-08-06** — boat min-pax is now the engine's `min-occupancy` menu entry (`../engine/SPEC.md §3`), and the multi-day course shape is `KindTemplate` (`§1.12`). The seed is constructible.

## P — Publish
- **P1 [unpublish is safe]** Given an installed copy, when the upstream is unpublished or re-versioned, the installed copy is **byte-identical** afterward — fork isolation.
- **P2 [owner-publish — the umbrella]** A signed-in owner publishes a **saved** bundle: the listing appears in the public catalog, carrying detailed information on what it is and what it does (listing copy required); another account can install it. Unsigned / unauthenticated publish is refused. **Verified in two halves, P2a and P2b** *(split 2026-08-29 — the one row was gated at three build steps while its verb half and its install half become executable at different ones; the row stays defined as the umbrella both halves report to)*. *(FD-82. Replaces the former absence test that forbade any user surface.)*
- **P2a [publish — the verb half]** `catalog.publish` from a **signed-in owner credential** against the service mock succeeds, and the listing appears in `catalog.list`; an unsigned or unauthenticated publish is refused. *(`SPEC.md` §2 + `INTERFACES.md` §1.)*
- **P2b [publish — the install half]** The published listing carries its **listing copy**, and a second account installs it. *(`SPEC.md` §2.)*
- **P3 [save is not publish]** Saving a bundle for the owner does not list it. Catalog listing happens only when they press publish.
- **P4 [no extract]** Asking to publish a **populated** board (counterparties, bookings, records) is refused. The agent names the lawful path: author / save-as-bundle (blanked shape), then publish that. *(Engine no-export; `SPEC.md` §2.)*
- **P5a [unpublish — the verb half, good-agnostic]** `catalog.unpublish` removes the item from `catalog.list` for **either good**; a caller who is not the listing's own publisher is refused. *(`SPEC.md` §2's unpublish law + `INTERFACES.md` §1's verb note.)*
- **P5b [an unpublished template stops being installable]** After unpublish the template can no longer be installed, and the copy installed before it is **byte-identical** — P1's law, cited rather than restated. *(`SPEC.md` §2.)*
- **P5c [unpublish never reaches an entitled skin]** *Given* an entitled account with a store skin installed and its pack persisted on-device, *when* that listing is unpublished, *then* the **entitlement and the on-device pack copy are both unaffected** — the skin-side mirror of P1. Unpublish is a **catalog** event; this row asserts nothing about an entitlement event, which is a different thing entirely (`SPEC.md` §4's non-collision note). *(`SPEC.md` §3's skin bullet.)*
- **P6 [deleting a saved bundle]** An owner deletes a saved bundle: it is removed, and a listing already published from it is unaffected. *(`SPEC.md` §2's delete-saved.)*
- **P7 [re-publish lists the newest]** A re-published bundle: the catalog lists the **newest** version, and installs from then on fork that version. *(`SPEC.md` §2's "the catalog lists the newest".)*
- **P8 [a skin publish from an owner credential is refused]** Publishing a **skin** from an owner (non-admin) credential is refused, **with the lawful path named** — the admin pack pipeline. *(`SPEC.md` §0's skins-stay-admin + `../security/SPEC.md §11`'s two-paths-per-good mirror.)*

## I — Install
- **I1 [snapshot fork]** Installing writes a provenance-stamped local copy (`createdVia: install`, source id + version); no live link, no subscription record exists anywhere.
- **I2 [parameters via propose→confirm]** Installing "Free Time Available", the agent walks each blanked parameter as an ordinary proposal — *their* 30 minutes is their setting — and **nothing writes without confirm**. *(A: Sofia would have installed this instead of authoring from scratch.)*
- **I3 [validated at the door]** A tampered bundle (any F1/F2/F3 violation) is refused **whole**, with the failing entry named — no partial install.
- **I4 [installs compile to normal writes]** The post-install board state is byte-equivalent **in shape** to the same setup authored by hand through the console. *(C: an installed dive bundle equals the hand-built setup behind Hug Ocean's week.)*
- **I5 [uninstall keeps the past]** Uninstalling removes the source document only; every rule and commitment already confirmed stands unchanged.
- **I6 [authoring ≡ hand-authored; provenance gates shipping] `[MUST]`** A template **authored through the owner's agent** (the `SPEC.md §2` authoring path — generative-UI + rule writes + shared/resource shapes) validates as a bundle — **against the authored set (`SPEC.md §1.2`'s split); publish-assigned fields are absent by definition and their absence is not a validation failure** — **byte-equivalent in shape to a hand-authored one** — the authoring twin of I4, mirroring engine `../engine/SCENARIOS.md` W5's agent-authored ≡ hand-authored principle. And a **production catalog default exists only if founder-authored through the app**: assert **no developer-authored bundle can be a shipped default** — provenance, not content, is what qualifies it. *(FR38's prove → save → ship path.)*
- **I7 [skin install grants through the seam]** Installing a store skin against the mock: the entitlement arrives through `entitlements.grant` (`INTERFACES.md §1` — a real granted state, never a pre-seeded map), the pack fetches via signed URLs, and the copy **persists in the app-managed on-device store** (`SPEC.md §3`) — assert it survives HTTP-cache eviction and serves S4/S6's laws offline. *(Added 2026-08-21 — Step 2's end-to-end gate previously ran against a pre-seeded entitlement while calling itself the contract test.)*
- **I8 [the install walk is a session, at dive-center scale]** Installing the dive-center seed (dozens of blanked parameters), the walk is **abandoned halfway**: the fork and its `draft` (disabled) rules persist — visible, resumable, nothing outward fired, nothing half-applied as live; resuming completes normally; uninstalling the partial removes the fork and drafts while anything already confirmed stands (I5's law). *(Added 2026-08-21 — the only install scenario was the smallest possible bundle, and the walk had no session state at the scale F5 sells.)*
- **I9 [a newer manifest version refuses whole]** A bundle stamped with a **newer catalog-manifest version than the client's** refuses **whole**, with **both versions named** in the refusal. *(`SPEC.md` §3's door-compare rule.)*

## E — Entitlements & degradation
- **E1 [entitled fetch]** An entitled account receives short-lived signed URLs for a store skin's derivatives; an unentitled account receives none — and the **palette-only preview still works** for both.
- **E2 [degrade to shipped]** Service unreachable → everywhere the app offers skins offers **the shipped four + Plain, plus any installed pack already persisted on the device**, at full function — a citing restatement of `SPEC.md` §4's degradation law. *(Rewritten 2026-08-29: "exactly the shipped four + Plain" contradicted I7, which asserts the device copy serves S4/S6 straight through an outage.)* *(Drives `../app/SCENARIOS.md` S6.)*
- **E3 [installed survives outage]** Service unreachable → every installed template remains fully functional — installed is local forked data.
- **E4 [nothing licensed leaks — content-based]** No licensed derivative is reachable by an unentitled account **in any form**: no long-lived or cross-account-reusable URL, and **no rendition inlined as data** in any unentitled-reachable document (the LQIP data-URI case, FD-31), nor any public artifact (repo, client bundle, cache header that outlives the signature). *(Restated content-based 2026-08-21 — scoped to URLs, this scenario structurally could not see the 24px inlined copy of the photograph being sold.)*
- **E5 [withdrawn entitlement deactivates at the next check] `[MUST]`** *Given* an account entitled to a store skin, with that skin **active and in a fave slot** and its pack persisted on-device, *when* the closed service withdraws the entitlement and the next entitlement check occurs (skin activation, or app open), *then* the skin **deactivates**, its **fave slot clears**, and appearance falls back to the shipped four + Plain. Assert the **device copy is not deleted**, and assert **no reason for the withdrawal crosses the seam** — the open half observes entitlement state only (`SPEC.md §5`). *(FR14.)*
- **E6 [offline never revokes] `[MUST]`** *Given* the same withdrawn entitlement, *when* the service is unreachable so no check can complete, *then* the last-known entitlement stands and the skin keeps rendering at full function — no flash, no error wall, no outage-triggered downgrade. Revocation lands on the **next successful check**, never on a failed one. *(FR14 × the degradation law; guards `../app/SCENARIOS.md` S4/S6.)*

- **E8 [pack grammar staleness degrades, visibly]** A pack the grammar has moved past **degrades to the shipped floor with the honest surface shown** — never silently, never a stale store action, never an error wall. *(`SPEC.md` §4's evolution rule.)*
- **E9 [a withdrawn template entitlement never reaches the fork]** *Given* an installed template, *when* its entitlement is withdrawn, *then* the installed fork is **untouched** — no rule disabled, no commitment moved — and **re-install is refused**. *(`SPEC.md` §4's withdrawal clause.)*

- **E7 [no board ledger write]** Exercising the store's entitlement and transaction surface against the service mock produces **zero** writes to any board money record — asserted as absence across the ledger tables, not as a balance check. The store is a different lane from value between users on boards (`SPEC.md §5`; the invariant is indexed in `SPEC.md §8`).

## D — Discovery
- **D1 [category at publish]** Every published item carries exactly one category from the closed set + tags, assigned at publish by the owner; the browse riser groups by them.
- **D2 [featured is curated]** A featured shelf shows only admin-flagged items; **no computed ranking exists in v1** — asserted as absence.
- **D3 [preview per good]** A skin card renders the owner's own board re-tinted; a template card renders the proposal-card anatomy + the ghost guest page from the owner's **real** availability — both display projections, zero writes, watermarked preview. **The template half asserts its absences by name** *(2026-08-29 — "zero writes" left FD-34's "mints nothing" to be inferred, and an inference is not an assertion)*: **no Shared row is created and no token digests are written** by the ghost, asserted as absence.
- **D4 [popularity reserved]** The catalog document carries the `popularity` field; no v1 surface sorts by it — asserted as format presence + UI absence.
- **D5 [the suggestion is the entry]** A need the catalog can serve, expressed in the owner's own turn: the template suggestion arrives as an **ordinary proposal card inside that turn** (FR-A — the card is the preview's door), linking to D3's preview; assert the browse riser **never self-opens** and no store surface appears unprompted or on a trigger firing. *(A′'s opening beat — "she does not go looking for a store; the agent brings it to her" — previously the one INDEX-named beat with no scenario.)*
- **D6 [the catalog renders in the viewing owner's language]** *(FR32, founder-ruled 2026-08-07 — a ruled law with zero scenarios in any suite until 2026-08-22; `SPEC.md §6`.)* The same catalog fetched by an owner whose stored language (FR15's setting, reused) is Thai renders category names and bundle `domain` display naming in Thai where translations exist; an entry with no Thai translation renders in **English** (the printed fallback) — asserted **per entry**, so a mixed shelf is lawful and a blank is not. An owner with English stored sees English throughout. Zero writes; the language setting never rides a store transaction.
- **D7 [the text filter is the only finding aid]** The client-side text filter over name + tags filters as specified, and **no search machinery exists** — asserted as absence, D2's pattern. *(`SPEC.md` §6's only-finding-aid sentence.)*
