# annnä Deployment — spec package

annnä is four layers — **Model / Harness / Engine / App** (`../README.md`) — with `marketplace/` and `security/` beside them, and this package is **the discipline of the build**: how code gets from a builder's keyboard to production. Environments, what may land on main, the spec/code boundary — "deployment" here means the whole delivery discipline, not just the last push.

**This package governs the build in this repo** — ruled in place 2026-08-07, reversing the 2026-08-06 separate-repo posture. The repo remains the public spec artifact and **keeps its direct-to-main flow** (founder-confirmed 2026-08-07); the re-scope pass that discharges that flow has run, deleting the branch/PR/worktree machinery rather than deferring it (`SPEC.md` preamble). Everything here binds the build from its first code commit. The bookend: `marketplace/` builds last of all — **deployment builds alongside**, with **Steps 0–1 before any layer's `BUILD.md` Step 0** and Steps 2–4 landing as the things they gate come into existence (the rung ladder when a hosted rung does; the ladder drills Z1/Z2 at app Step 0, the first moment production has content). Every gate is kept; the re-scope moves when they land, never whether. Normative home: `SPEC.md §0`.

**The two-repo topology — superseded 2026-08-07 (build ruled in place; no separate code repo, no vendored snapshot; kept for provenance):** a new **private** code repo holds the build and **vendors these specs as a pinned snapshot** — the repo's own install law applied to itself. Design changes happen here, then re-pin (batched per swap pass); the vendored copy is read-only and its content hash is verified on every CI run.

**Vocabulary warning — read before anything else.** The harness owns *agent, loop, trigger, parallel, unattended* — and bare *session* — for the product's runtime. This package always uses compound forms: **builder** (a development-time session authoring code — inherited harness vocabulary, not coined here) · **builder session** (one builder's run of work on one layer) · **wave** (concurrent sessions the dependency order permits) · **rung** (an environment) · **lane** (a CI job class). Deployment prose says *concurrent*, never *parallel*. The full glossary is `SPEC.md §2`.

**This folder's purpose:** the complete discipline. Read in order:

1. **`SPEC.md`** — the law: one repo and the spec/code boundary (spec files on the floor, never moving in the same commit as code), the three rungs (production activates at app Step 0) and the mock/exposure laws, the landing law (author ≠ approver, the always-run aggregator, gate-coverage, determinism), the swap order and its diff gate, the process floor, the DR rulings.
2. **`INTERFACES.md`** — the seams: the layers' `Gate:` lines as contract, the spec/code boundary, the security-package composition, the substrate (GitHub · Cloudflare · Convex — named there only), the now-optional scratch rehearsal.
3. **`SCENARIOS.md`** — the proof: `[MUST]` rules enforced by named mechanisms and verified by refusal or static assertion; `[DRILL]` walks executed once and recorded.
4. **`BUILD.md`** — the ordered plan. **Steps 0–1 before any layer's Step 0**; Steps 2–3 land with what they gate; Step 4 fires at app Step 0.

**Definition of done:** every `[MUST]` scenario is enforced by a **named mechanism** in this repo — a required CI check, a script, never a convention in prose; every pre-app `[DRILL]` has one recorded execution; the Z1/Z2 ladder drills are deliberately pending until app Step 0 and recorded then. On that basis — mechanisms live, pre-app drills recorded — `../harness/BUILD.md` Step 0 begins.

**Deliberately NOT here:** runtime operations of the shipped product (monitoring, on-call, incident response — a post-launch package) · launch and exposure mechanics (DR-2) · billing or payment infrastructure (the closed service's problem) · the layer build orders themselves (each layer's `BUILD.md` owns its steps; deployment only sequences *between* layers).

Open rulings are held in `SPEC.md §8` as the **DR-n** series. This package was hardened by **adversarial review round one** (four lenses, 42 findings — the record and kill list are in `NOTES.md`); one of its findings hardened an orchestration-runtime pin from a risk note into law, and the 2026-08-08 re-scope (FD-4) then deleted the orchestration law and the pin with it — there is no runtime left to pin (`NOTES.md`).

## The one green command

*Moved here from `../AGENTS.md` 2026-08-08: it is reference read once while debugging a red gate, and AGENTS.md is every session's first read. This is deployment's content — the gates are this package's mechanisms.*

`npm run check` from the repo root is the whole gate. `.github/workflows/check.yml` runs exactly it on every push — one always-run aggregator job, **no path filters** (a skipped required check reports as success, so a filtered gate is worse than none: `SPEC.md §4`). That job reports *after* a landing, so it is the second reader, not the refusal. **A `.githooks/pre-commit` hook runs `npm run check` before every commit** — the pre-landing form `SCENARIOS.md` B1 pre-authorized, with `--no-verify` as its acknowledged bypass. The hook is not automatic on clone: `git config core.hooksPath .githooks` once, per checkout — **a fresh clone is ungated until that line is run**. FD-7 accepted this form and wrote the bypass down as the ceiling, which is the condition B1 named for returning to `[MUST]`; it is one now, with a stated bound rather than none.

**What each step is for.** The *order* is `package.json`'s check chain and lives only there — it is executable, so it cannot go stale, and this list claimed an order that was wrong in two places until 2026-08-08. This list is the **why**. It is unnumbered on purpose, and `scripts/roster-check.mjs` asserts it names every script in `scripts/` and nothing that isn't there.

- `scripts/gate-coverage.mjs` — every `[MUST]` scenario has a BUILD home, every gated ID is a real scenario. Its own `--selfcheck` assert suite runs first, so the checker is checked before it checks. **And the checkpoint ledger** *(2026-08-22)*: parses `../harness/BUILD.md` Step 5's declared checkpoints and asserts (a) every gated ID sits in **exactly one** checkpoint — the step's own stated law, previously uncounted — and (b) every pair on the printed **Depends** line (`ID → (n)`, the Given-needs-machinery edges) matches the ID's actual placement, so moving D4 out of the ladder checkpoint fails the chain instead of going green vacuously through the empty-list path. **What it cannot check:** that the Depends line is *complete* — naming a new Given-dependency remains a reading job; enforcing a named one is mechanical.
- the static scenario gates, all local — `s2-path-class.mjs` (S2: spec and code never move in one commit; **spec is decided by file extension, not directory**, because layer code will live beside its specs), `s3-no-outside-spec.mjs` (S3: no submodule or workflow pulls spec text from outside the commit), `r3-workflow-lint.mjs` (R3: the model key is referenced by the qualification lane and nowhere else), `r9-noindex-nodebug.mjs` (R9: no reachable debug or auth-bypass flag below production), `x1-secret-grep.mjs` (`../security/SCENARIOS.md` X1: no client-exposed secret), `r2-closed-service.mjs` (R2: no closed-service credential and no undeclared service URL), `r4-one-seed-door.mjs` (R4: at most one `seed.<ext>`, importing fixtures only), `r6-deploy-secret-scoping.mjs` (R6: no unprotected CI job holds a deploy/production secret). S2 classifies the **resulting commit** — in the hook, the staged set unioned with HEAD's paths when amending; in CI, every commit in the pushed range (`--range`/`--commit`).
- the engine and harness vitest suites.
- `scripts/b9-twice-run.mjs` (B9) — every layer with a suite runs **twice** and its `.tmp/transcripts/<layer>.txt` is byte-compared. Both layers write one since harness Step 0, so this is a live byte-compare, not a placeholder; a suite that stops writing its transcript while a sibling still writes one fails it. `--selfcheck` first, same reason as gate-coverage.
- `scripts/egress-lint.mjs` — outbound network calls confined to `egress-allowlist.md` (two files, both process-only). `q3-swap-diff.mjs` runs its `--selfcheck` here and its real pass in `.githooks/commit-msg`, which needs the commit message. **A second hook exists for that**, and it needs the same one-time `core.hooksPath` line.
- `../engine/scripts/reactive-push-check.mjs` — **only where a live deployment exists.** It needs one, and CI has none, so `check` runs it when `CONVEX_URL` names a deployment and prints an explicit *skipped* line when nothing does. Run it yourself against the dev deployment before trusting the criterion; the CI job cannot.
- `scripts/size-guard.mjs` — no tracked file over 2MB, except `assets/masters/treestars.jpg` and `koi.jpg`, pinned by path **and exact size** so a swap at the same path cannot pass on the name. They are unreachable without a history rewrite, which `SPEC.md §7` forbids.
- `scripts/package-shape.mjs` — every package with a tracked `SPEC.md` carries the five files `../AGENTS.md` §Package shape promises, so the eighth package is checked the day it lands. `model/`'s `EVALS.md` is a substitution, declared in the script.
- `scripts/claim-check.mjs` — a number stated in prose must equal what it counts: `../AGENTS.md`’s gate count, R2's declared hosts, FD-4's surviving scenarios, and — since 2026-08-29 — three more that were countable and unguarded. **`../AGENTS.md`'s open-ruling sentence**: the count word must equal the labels beside it, no label may sit in the open *and* closed lists at once, and every label declared open must be defined somewhere in the tracked corpus, because an open ruling no file defines is one nobody can read. **The root `README.md`'s situation counts**: the sentence states two numbers over one directory and the split between them is the point — the primes are marketplace install probes, not end-to-end situations — so each is counted the way the sentence itself divides them. **The package-shape set**: `../AGENTS.md` prints the five files as law and `package-shape.mjs` enforces them, two copies of one set that nothing compared; set difference is asserted **both ways**, since a one-directional compare passes a superset, which is how a shape law grows a sixth file nobody promised. Most drift here is the corpus miscounting itself. **What it deliberately still does not check:** a *historical* number — `README.md`'s finding count names a set that no longer exists, and a check that cannot fail is worse than none. `cite-check.mjs` is advisory only (`npm run cites`) — it cannot tell an invented ID from a review-finding number.
- `scripts/doc-count-check.mjs` — the tracked markdown count `../AGENTS.md` and the root `README.md` claim must be true. Add or delete a tracked `.md` and it reddens until both are corrected.
- `scripts/index-complete.mjs` — `../INDEX.md` names every tracked `.md` and nothing else. The index exists so an agent can pick three files instead of grepping the corpus, and that only works while it is complete: an index missing three files reads as exhaustive and is trusted as one. It is the set to `doc-count-check.mjs`'s count — the same pairing `roster-check.mjs` makes one level over, and for the same reason. What it cannot check is whether a description is still *true*; if a row and its file disagree, the file wins.
- `scripts/agents-budget.mjs` — `../AGENTS.md` is every session's first read, so its length is a cost every reader pays at every session start; this bounds it. A **ratchet, not a target**: raising it is a deliberate one-line diff in that script, which forces “what did I delete?” to be answered first. Prefer moving a section to the file that owns its subject — which is how this section got here.
- `scripts/status-report.mjs` — the build-status block, derived from each `BUILD.md`'s own markers rather than hand-written. It also prints every `NOTES.md` **`## Still open —`** section (2026-08-23), splitting **founder wants** — features asked for and deliberately not yet planned, whose titles begin *"the founder"* — from the rest of the backlog. A want that only a working document points at is a want the next session does not find; this is the pointer that ships in the clone.
- `scripts/ignore-claim.mjs` — a directory `../AGENTS.md` calls gitignored must hold **zero** tracked files. Written 2026-08-08 after `.specs/` was described as absent for every reader while three of its files shipped in every clone — and were counted in the tracked total asserted one sentence earlier.
- `scripts/cite-form.mjs` — **no in-repo citation may name a line number** (`../AGENTS.md` §Citation conventions). A line number rots the next time anything is inserted above it, silently; quote the phrase instead.
- `scripts/cross-layer-cite.mjs` — a citation that **names** a `SCENARIOS.md` file *and* an ID must resolve: that file must define that ID. `SCENARIOS.md` Q3 pointed the swap law's **Z2** at the *harness* scenario file for two days — the harness defines no Z family at all, Z2 lives in `engine/`, and it was the citation for the one mechanism the four-layer bet rests on. *(Named in prose rather than quoted as a path here, because quoting the broken form verbatim is itself a dangling citation, and this gate catches it — as it did while this line was being written.)* Nothing could see it: `gate-coverage.mjs` never follows a path out of a layer, and `cite-check.mjs` deliberately **drops** anything qualified by another layer's name, so the more precisely a citation was written the less any gate looked at it. It **refuses** where `cite-check.mjs` only reports, and that difference is the point — a bare `[A-Z]\d+` names three registries here and needs a heuristic, while a citation that states its own path has nothing to be wrong about. Both corpus forms are carried (ID inside the backticks and ID after), ranges check both endpoints, and both resolution bases are tried because `../AGENTS.md` says the corpus mixes relative and repo-root-relative. **Widened 2026-08-29 to SPEC-target `§` citations** — the corpus's densest citation form, `` `engine/SPEC.md §1.12` ``, was checked by nothing, and a plan claiming this gate as proof for it took a Codex BLOCKER. A citation naming a `SPEC.md`, `EVALS.md`, `INTERFACES.md` or `BUILD.md` **and** a `§` reference must resolve in that file: **1312 of them do.** Two traps had to be handled, and both would have produced false reds. **`§6.5` means item 5 of `§6`'s numbered list, not a subsection** — `engine/SPEC.md` states this in its own header because *three* separate automated checkers filed it as a phantom-section bug and were wrong all three times; resolution therefore tries a heading first, then item M of §N's numbered list, and only a ref that is neither fails. And **the `§` sigil is not written in headings everywhere**: `engine/` and `deployment/` write `## §1.`, while `harness/` and `model/` write `## 1.` with no sigil, though citations use `§` in both directions — requiring it in the heading reported 464 dangling citations against a corpus that had none, caught only because the first live run was read rather than assumed. Both are pinned by selfcheck assertions, the numbered-list *positive* being the one that must never be dropped for brevity. **What it cannot check:** whether the cited scenario or section still *supports* the sentence — existence is mechanical, aboutness is a reading job; and **named** section refs (`§Law tiers`), which have no closing delimiter in prose, so any matcher for one guesses where the name ends and a wrong guess reds a correct citation.
- `scripts/hex-source.mjs` — **every colour answers to something.** A hex in tracked markdown must appear in a shipped pack's `palette.json` or in `../assets/make-pack.mjs`, or declare itself derived. `PR/BRAND.md` already carried the rule — *"No hex may appear in brand material that is not in that file"* — and nothing enforced it, so it bound as far as the author's memory and no further. Written 2026-08-09 after `app/DESIGN.md` §Colour, whose entire subject is that colours must be sourced, introduced two hexes of its own attributed to a file that does not contain them; **three unsourced-value errors were made in that one sitting** and a hand sweep found them four hours later. Only **backticked** hexes are read, which is a discovered convention rather than an imposed one — a survey found every colour in the corpus backticked and the one non-colour (a PADI number in a user story) bare, so the false positive costs nothing to avoid. The derived escape is **per line**, never per section: a section-wide exemption would have covered the two invented hexes as readily as the three real ones. **What it cannot check:** whether a value marked derived is *correctly* derived — that needs the derivation re-run against four photographs — or a colour written without backticks. Both bounds are printed on every green run.
- `scripts/pack-shape.mjs` — **every shipped pack carries exactly the fields the spec enumerates.** `../marketplace/SPEC.md §1.1` names the palette's sixteen stored fields, and the enumeration had already gone stale against the packs once in each direction — the 2026-08-22 pair (`brightestRegion`, `veil`) existed in prose and in no pack, while treestars carried three fields no spec named (a pre-corpus per-pack accent note the derived-accent law and the no-skin-is-special ruling had both superseded). A pack missing a field or carrying an unlisted one is refused — the install door's own discipline applied to the shipped fixtures. **What it cannot check:** whether a derived field is *correctly* derived — the install-door floors at app BUILD Step 1 own that, and the bound is printed on every green run.
- `scripts/design-law-coverage.mjs` — **every section of `../app/DESIGN.md` is accounted for by `../app/BUILD.md`**, cited as `§Name`: either a step gates on it, or BUILD says in words why none does. `DESIGN.md` gates build steps by *human review*, and each step named its covered sections by hand — so when three normative sections landed in one sitting (§Shapes, §Colour, §Typography) all three gated nothing, and no gate here could see it, because every other gate compares a document to a **countable fact** and none compared one document's sections to another's coverage of them. It is a design-system-growth defect that recurs by construction: the remaining UI/UX phases each add a section. The match requires the `§` form deliberately, so a pass is a citation a reader can follow rather than an English word colliding by luck — "Console" and "Language" would match almost any paragraph bare. **What it cannot check:** whether the review happened or was done well. `../TDD.md` keeps design law a human checklist on purpose; completeness is countable, judgement is not.
- `scripts/seam-async.mjs` — **every seam call is a promise** (`../harness/INTERFACES.md §1`'s async law, 2026-08-22). The seam interfaces were written value-returning against neighbours that are all async in practice, and the swap law (Q3, zero harness changes) forbids the fix at the moment the first real adapter needs it — so the shape is pinned now, while it is a rename. Asserts every `*Seam` method in `harness/src/seams.ts` returns `Promise<…>` and the clock carries `sleepUntil` while `now`/`step` stay synchronous. **What it cannot check:** that the loop *awaits in the order* the three ordering laws require — that is the suite's job, over behaviour; the bound is printed on every run.
- `scripts/trigger-union.mjs` — **a closed enum stated in prose and in a type is compared, not trusted.** `harness/SPEC.md §4`'s trigger sources and `harness/src/index.ts`'s `TriggerEvent` union had already drifted when this was written — the delivery report joined the spec 2026-08-21 while the union sat at five, inside a step marked CLOSED. Set equality up to naming, both directions, count included. **What it cannot check:** other prose⇄type enum pairs — each gets this treatment when its second copy exists. **Its second checked pair landed on that hook** *(2026-08-28)*: the stored-object read member carrying the backticked `FiringEvent` token in `../engine/SPEC.md §5` item 7 and in `../harness/INTERFACES.md §1.1` — prose⇄prose this time — asserted to exist in both files and to carry the **identical** token, so a member named one thing in one file and another in the other is a red, not a warning. The checked pair prints on every green run.
- `scripts/compat-reasons.mjs` — **the refusal vocabulary has one home and code stays inside it.** `../harness/INTERFACES.md §7.1` enumerates the closed reason set per kind (authored 2026-08-22 as `harness/COMPAT.md`, ahead of Step 8 because stubs consume it from Step 1, and **folded** into the seam file 2026-08-29 when the harness package returned to its ruled five files); this asserts §7.1's kinds equal that file's own §1 envelope sentence — **two enumerations inside one file, which can still drift** — both ways, that every kind carries a reason, and that every `reason:` literal in harness code is enumerated — widening by code is refused, because widening is a breaking change (RQ-13). **What it cannot check yet:** the reverse — that every enumerated reason is exercised by a suite; checkable as the Step 1–5 suites land, printed as the bound until then.
- `scripts/mint-revoke-pairing.mjs` — **every mint proves its revoke, at class level.** The per-object revocation laws all existed and every one was tested; nothing ever compared the **classes of standing thing this system mints** against the scenarios that undo them, so a mint whose undo had no scenario passed every gate while being a capability with no way back. It parses the closed mint-class list out of `SPEC.md §4`'s bullet — one home, no second copy — and asserts each printed class carries a `mint ↔ revoke` pair whose two scenario IDs both resolve in the files they name. It found one on its first pass: channel suppression had **no re-enable scenario in any layer**, which is why `../harness/SCENARIOS.md` D29 exists. **What it cannot check:** whether the paired scenario's assertions actually *exercise* the revoke, or cover every holder form of the thing minted — checkable as the Step 1–5 suites land, printed as the bound until then (`SPEC.md §7a` item 15).
- `scripts/probe-coverage.mjs` — **every requirement names its falsification probe or declares the debt.** The `RQ-##` register and the probe corpus shared zero referents when this was written — they could drift forever without contradicting each other. Asserts `../PRD.md §4.6`: every defined RQ has an anchor row and every row names an existing Situation or declares `probe: owed` with what the owed probe must show; an `owed` row is a debt kept visible, never an exemption. **What it cannot check:** whether an anchored beat actually *exercises* its requirement — existence is mechanical, aboutness is a reading job.
- `scripts/t-six-before-link.mjs` — **no public link before T1–T6 green, mechanized** (`../security/BUILD.md` Step 4's printed gate was prose, and the deployment guardrail says a rule enforced only by prose has gone wrong). The marker `../security/t1-t6-green.md` is required once the tree holds **both** a token route under `app/` (the guest capability-link surface) **and** a tracked rung config under `app/` — the thing that makes the app publishable. **Re-cut 2026-08-29 from presence to publishability** *(L-221 / S13)*: the printed law is that no link goes **live** before T1–T6 are green, and tracked-route presence is not liveness — the old trigger reddened `../app/BUILD.md` Step 0's first commit four steps before the marker could legitimately exist, which was the one named blocker on the app build. Step 0's first commit lands routes with no rung config, so the gate stays **armed** and green through it; the commit that makes the app publishable is the last state this repository can observe before a link is live, and that one requires the marker. **The law is re-affirmed and only the trigger moved** — and the loosening is bounded by the selfcheck, not by this paragraph: publishable-and-unmarked must fail, and the armed case must pass. "A rung config" is imported from the one definition `r9-noindex-nodebug.mjs` also reads, so a host swap moves it once (`substrate-swap.md` names what a forgotten second copy costs: "a dead gate"). **What it cannot check — three bounds, the third being the one that matters:** that the app is actually deployed (the tree cannot see production) · that the marker's green was earned (the suite's fact) · **that deploy is actually gated on a *tracked* rung config, rather than on configuration the deploy workflow supplies inline.** `SPEC.md §4` rules deploy continuous and no deploy workflow exists yet, so nothing in the tree proves a deploy is impossible without one; under that architecture a token route could reach production while this gate stays armed and silent. The trigger is the best proxy the repository can observe today, not a proof — **re-verify when `BUILD.md` Step 2 and Step 4 stand up the first rung**, the commit where the real deploy path becomes readable.
- `scripts/roster-check.mjs` — set equality between this list and `scripts/`. It exists because `claim-check.mjs` verified the gate *count* while `b4-verdict-check.mjs` appeared in no roster at all: a count and a roster that are never compared to each other can both be right and still hide a gate.
- `scripts/gate-wiring.mjs` — every script in `scripts/` is named by some `npm` script in `package.json`, and the set of files exempt from that rule has exactly **one** definition. Counting a gate and running it are different facts: a script dropped in this folder was counted by `claim-check.mjs` and described in this list while nothing ever executed it — three green gates over a script that had never once run. The exempt set was the older defect, declared twice, in two gates, agreeing by luck and feeding two separate counts with neither citing the other; it now lives in one data-only module that every consumer imports — unnamed here deliberately, because this section is the gate roster and `roster-check.mjs` refuses a non-gate listed in it. **What it does not check:** whether a wired script runs inside `check` specifically. `b4-verdict-check.mjs` and `cite-check.mjs` report rather than refuse and run under their own scripts by design, so "named by some script" is the honest bound — tightening it to the chain would either redden those two or need an exemption list, which is the second copy this gate exists to prevent.
- `scripts/b4-verdict-check.mjs` — **reports, never refuses, by design.** It runs as `npm run verdicts`, not in `check`: a blocking verdict gate would deadlock the first commit (`SPEC.md §4`), and B4's structured verdict is the human's to cast and cannot be self-cast.
