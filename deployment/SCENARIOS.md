# annnä Deployment — SCENARIOS (the process, falsified)

*Pass/fail, mechanical, replayable. Two tags: **`[MUST]`** — enforced continuously by a named mechanism (required CI check, script); verified by attempting the forbidden act and observing refusal where an attempt is runnable, and by **static assertion** where the forbidden thing is an absence (a credential, a code path) — you cannot attempt with a credential that doesn't exist. **`[DRILL]`** — executed deliberately at least once, result recorded: the tag for what only a runtime or a human can enforce (the process analogue of the harness's `[HELD-OUT]`). Rehearse what is rehearsable on a scratch repo if desired (`INTERFACES.md §6`); the canary and drills run for real, here, before the first layer lands. (Section letters are local to this file.)*

## R — Rungs
- **R1 [prod credentials absent below] `[MUST]`** Enumerating each lower rung's env store and diffing against the manifest finds no production-tagged secret; and the preview-creation credential cannot read the production deployment (token-scope assertion).
- **R2 [closed service unreachable] `[MUST]`** No closed-service credential and no real closed-service base URL appears in any code, config, or CI environment below production — static check; there is no code path to reach it.
- **R3 [model key confined] `[MUST]`** The model-provider secret is referenced only by the protected qualification environment; a workflow lint fails the build if any other lane references that secret or environment.
- **R4 [one seed door] `[MUST]`** Exactly one named seed entrypoint exists, and its module statically imports only the fixtures bundle — no network, no store dump.
- **R5 [manifested secrets] `[MUST]`** Each rung's env store diffed against the env manifest shows no unmanifested secret; the production half of this check runs only inside the protected deploy environment.
- **R6 [no deploy secret meets agent-authored code] `[MUST]`** No deploy or production secret is present in any CI job that executes agent-authored code — job/environment scoping, proven by an env-dump canary showing absence.
- **R7 [production refuses anonymous] `[MUST]`** From app Step 0 onward, an anonymous request to production is refused — deployment protection, attempted and observed.
- **R8 [qualification lane capped and human-fired] `[MUST]`** The qualification key carries a provider-side hard spend cap, and the lane's protected environment requires the human identity as reviewer — a non-human trigger attempt is refused.
- **R9 [lower rungs unindexed, undoored] `[MUST]`** Non-production rungs serve `X-Robots-Tag: noindex` and contain no reachable debug or auth-bypass flag — config/grep check (the security X1 pattern).
- **R10 [rotation proven] `[DRILL]`** Each rung's secrets rotated once; the rung rebuilds green.
- **R11 [mail sandboxed below production] `[MUST]`** No production mail credential appears in any rung below production — static check over the env stores and the manifest — and a send attempted from a lower rung lands in the provider's sandbox, never in a real inbox. The mock law's mail clause, given the named mechanism R2 and R3 already carry (`SPEC.md §3`).

## B — Landing law
- **B1 [red does not survive undetected on main] `[MUST]`** A commit whose declared gates or layer suite are red reddens the always-run aggregator (`npm run check`) — proven by a **canary red test**; no path filters, so a skipped check can never read as success. **`[MUST]` since FD-7**, on the condition this scenario itself named: `.githooks/pre-commit` execs the aggregator before the commit lands, which is the *pre-landing hook with its bypass accepted as the ceiling*. **The ceiling, stated:** `--no-verify` defeats it, and the hook is per-checkout (`git config core.hooksPath .githooks`) — a fresh clone is ungated until that runs. `.github/workflows/check.yml` runs the same aggregator on every push since FD-10 — a second reader after the fact, not a second refusal. Canary fired and recorded 2026-08-08 (`BUILD.md` Step 1).
- **B4 [author ≠ approver, and the verdict is the human's] `[DRILL]`** The author is the **agent session**; the approver is the **human**. A change an agent authored and no human read cannot be the final state of main. What the human casts is a **structured verdict** — named findings, or an explicit *attempted to falsify; nothing found*; a bare "looks fine" is not one. `[DRILL]` rather than `[MUST]`, honestly: with one human and no bot identities there is no second identity for a check to compare against, so this is enforced by the human's own discipline and recorded, not by a mechanism. **Recorded as a `git notes --ref=verdict` note on the commit it judges** (`SPEC.md §4`); `scripts/b4-verdict-check.mjs` lists commits carrying none and never refuses one.
- **B8 [gate-coverage] `[MUST]`** A required check runs `scripts/gate-coverage.mjs` over each layer's `SCENARIOS.md × BUILD.md`: a change that adds or renames a `[MUST]`/`[ENGINE]`/`[HELD-OUT]` scenario without naming it in a BUILD step (an **orphan**), or names a BUILD gate ID no scenario defines (a **phantom**), fails the check — proven by a **canary**: an orphaned scenario reddens it. The script ships with an assert-based `--selfcheck` over an inline fixture; the graded model `EVALS.md` is out of scope (set-thresholds, not per-item BUILD homes).
- **B9 [determinism] `[MUST]`** The full layer suite runs **twice** in CI and the two transcripts are **byte-compared**; any divergence fails the build — the harness's L2 determinism (`../harness/SCENARIOS.md L2`) mechanized as a process gate. A transcript is `.tmp/transcripts/<layer>.txt`, written by the layer's suite (`SPEC.md §4`). The runner is wired now and exercised at harness-build time, when transcripts first exist — the R7 pattern. **It is not a dead script in the meantime:** it fails a suite that declares a transcript and writes none, and it names what it found rather than passing silently, so the day a suite starts writing one it is already under the gate.

## Q — The swap diff gate
- **Q3 [the diff gate] `[MUST]`** `git diff harness/` non-empty in a swap commit fails the check — a mechanical assertion, not a review comment. **A swap commit is one carrying the `Swap: <layer>` trailer** (`SPEC.md §6`, which also states the bound: an undeclared swap is not caught). This is the only mechanical guard on the **zero-harness-changes swap law** the whole four-layer bet rests on (`../harness/SCENARIOS.md Z2` and its per-layer twins), which is why it survives a re-scope that deleted the rest of this family.

## S — The spec/code boundary
- **S2 [spec and code never move together] `[MUST]`** A **commit** whose changed paths span a layer's spec files and that layer's code fails a required path-class check — the spec change lands first, and the code builds to it. (This is what the vendored read-only tree used to buy: a builder cannot edit the spec beside the test it is failing.)
- **S3 [no spec from outside the commit] `[MUST]`** No workflow, submodule, remote, or code path pulls spec content from outside the checked-out commit — static check over workflows and config, so the text the reviewer read and the text `gate-coverage.mjs` enforced are the same text. (Stated as no-fetch, not "no network route": egress absence is not provable on shared runners.)

## Z — End-to-end drills
- **Z1 [the ladder walk] `[DRILL]`** At **app Step 0** — the first moment production has content — the full ladder runs green once on a trivial change: change → the aggregator green → preview rung up → the human's verdict → land on main → production deploy behind R7. The deploy is the exam. Before app Step 0, main's terminal rung is CI-green and this drill is deliberately pending (`SPEC.md §0/§4`).
- **Z2 [revert deploys clean] `[DRILL]`** A merge is reverted; the revert deploys production clean — the reversibility the process floor leans on is real. Runs with Z1.

**Coverage map (SPEC § → scenarios):** one repo & the spec/code boundary (§1) → S2, S3 · rungs, data/secret/mock/exposure law (§3) → R1–R11 (the mail clause → R11) · landing law (§4) → B1 (red does not survive undetected), B4 (author ≠ approver) · the swap order (§6) → Q3 (the diff gate) · the process floor (§7) → Z2 (revert reversibility) · merge→deploy (§4) → Z1–Z2, R7 · corpus consistency & replay (§4) → B8 (gate-coverage), B9 (determinism). Every `[MUST]` names its mechanism here or in `SPEC.md`; a `[MUST]` enforced only by prose fails its own definition — which is why **B4 alone** of the landing-law pair is a `[DRILL]`: its second identity does not exist and no mechanism can invent one. B1 was the other until FD-7 accepted the pre-commit hook and its `--no-verify` ceiling; it is now a `[MUST]` with a stated bound rather than a `[DRILL]` with none.
