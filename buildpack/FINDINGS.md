# Findings register

Every row is a hypothesis with the evidence it rested on, never a closed door. A later reader may confirm it, challenge it or mark it unable to verify. Overturning a row succeeds when the overturn is supported by evidence or reasoning, including a counterexample derived from unchanged sources; it names the row and what it rests on. Reconsideration needs no changed source. This file is tier `history`: it justifies, it never builds. No row here outranks a `SPEC`; where a row and its home disagree, the home wins and the row is the defect. Rows carry attributed design reasoning only: no scores, tallies, readiness labels or execution plans.

To add a row: take the next free `F-nn`. Give it a date, a source, a one-line finding, and a verdict from the closed set — accepted / rejected / deferred / overturned / unverified. Evidence must be something a clone can resolve (a repository path in backticks); where the source is working material absent from clones, say so as "working material, absent from clones: <path>" — written bare, since it is not a path a clone can resolve. Name what evidence or reasoning would change the row; when the evidence cell already names the re-check that would overturn it (a re-read of the cited source, a re-derivation against the tracked tree), this cell may be left blank rather than repeat it. Leave the re-verification cell empty until someone re-checks the row, then record who, when, and the result.
