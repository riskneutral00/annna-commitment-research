# `_briefs/` — the input to an elicitation sitting

**What these are.** Each file here is the brief a `/probe-elicit` sitting runs from: the world it will ask about, the actors it expects to find, the rules whose *source* must be established, and — the load-bearing part — **the questions the founder must be asked**. A brief is provenance, never authoritative once its Situation lands; `../README.md` states that rule and this file does not restate it.

**The one discipline that makes a brief useful.** A brief states what must be **asked**, never what the answer is. A brief that answers its own questions has stopped being an elicitation input and become a **script** — and `../README.md`'s provenance vocabulary already rules that a scripted run "cannot refute" the list it was written from, so it can never count as coverage evidence. Writing the answers in advance is therefore not a shortcut to the same result; it destroys the result.

**Two kinds of brief live here, and they read differently.**

- `situation-d-debra.md` was written **after** its sitting, as the record of one. Its "Situations to cover" lists are answers, because by then they were answers.
- Every other brief here was written **before** any sitting, from the coverage debt in `../COVERAGE.md`. Their lists are questions. Do not reshape one into the other's voice.

**Each brief opens with a readiness condition, never a date** (FR2). A condition is a state of the world that can be checked; "later" and "after the next phase" are not conditions.

**Where the debt comes from.** `../COVERAGE.md` records 71 owed beats: 45 genuine coverage gaps clustered into fourteen elicitation subjects, 15 questions belonging to open ruling OR-42, and 11 deferred by FR1. A brief is owed per *subject*, not per beat — several owed beats one sitting would answer together share one brief. The OR-42 fifteen get **no brief**: they need a ruling, not an elicitation, and a story written before that ruling would be designing to a mechanism that does not exist. The FR1 eleven get no brief either; the referral flow is deferred with its machinery.

**One gap beat has no brief because it cannot have one yet.** `Situation-C/operator-dive-center-second-seat.md`'s *"The rules are the board's"* — that a rule authored by one named admin binds identically to a booking taken by a second — is downstream of **OR-42**. No seat object exists, so there is nobody for the second admin to be, and a brief would have to invent the seat the ruling exists to define. It waits for the ruling, in `../COVERAGE.md`'s owed list where it is visible.

**No brief exists for the freelance supplier's own board, and none may be written.** FD-68 holds the founder's own freelance life out as the product's first live test and forbids both eliciting it and drafting a fictional stand-in. `../COVERAGE.md`'s "Setup-only, no run" table carries the limit honestly. This is the most tempting missing brief in the folder and its absence is deliberate.
