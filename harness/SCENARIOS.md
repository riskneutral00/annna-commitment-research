# annnä Harness — SCENARIOS (acceptance suite / TDD substrate)

*Every decision in `SPEC.md`, turned into a pass/fail scenario. These are the harness's acceptance criteria: the harness is "done" when all **[MUST]** scenarios pass against the stubs in `INTERFACES.md`. Format: **Given / When / Then**, with the expected outcome. `[MUST]` = build-gating; `[SHOULD]` = built and tested — still in its BUILD step's Verify set — but not release- or derivation-gating (FD-59's demotion class); `[HELD-OUT]` = deliberately not designed-to, run as an out-of-sample generality check (record result, don't fix the atom to make it pass); `[ENGINE]` = the harness's part is only "hands the engine a representable state," the enforcement is verified later.*

*Write these as executable tests during `BUILD.md`; each build step names the scenarios it must turn green.*

## A. Harness 1 — board authoring

- **A1 [MUST]** — *Given* an empty board, *when* the owner says "put a dive lesson Thursday 3–4pm," *then* a Commitment is committed with an occupying start+end, `temporal_type = event`, and the app is asked to render it on the **board** surface.
- **A2 [MUST]** — *Given* A1's commitment exists, *when* the owner says "actually make it 3–5," *then* the same commitment is edited (not duplicated) and re-rendered.
- **A3 [MUST]** — *Given* a task ("email the report by Friday"), *then* `temporal_type = task` (end has role `deadline`, no occupying interval) and it completes **by action**, not by the clock.
- **A4 [MUST / poka-yoke]** — *Given* a board at capacity 1 with an active commitment 3–4pm, *when* a second commitment tries to consume it 3–4pm, *then* `commit` returns `conflict` and no double-book exists. `[ENGINE]` for the enforcement; harness must surface the conflict, not swallow it.
- **A5 [MUST / tasks reserve nothing]** — *Given* a start-only task at 19:00 (no end), *then* availability over that time is **unchanged** (a marker, not a reservation); *given* the same entry as an event 19:00–19:30 plus a 5-min buffer rule, *then* availability splits around 18:55–19:35. Same substrate, no extra machinery.
- **A6 [MUST / hand-edit transits the floor]** — *Given* the owner edits a commitment **by hand** on the board (direct manipulation, not an utterance — the app riser's *"edit by hand or by talking,"* `../app/SPEC.md §1` "Everything else is a riser"), *then* the write still transits `CRUD_Commitment` under the floor: a reversible field edit runs at full autonomy, and a hand-edit that would cross the line (e.g. changing a confirmed booking's counterparty-facing time) is gated **exactly as the utterance path is**. The app collects the edit and hands it to the harness untouched; the floor's applicability does not depend on whether the change arrived by hand or by talking.
- **A7 [MUST / tool return validated]** — *Given* a tool returns a value that does **not** match its declared return schema, *then* the harness surfaces a **structured error** and does not pass the malformed return to the model. Assert no raw or unvalidated return is ever consumed — the return leg is validated exactly as the call leg is typed (`SPEC.md §5`), **before the harness consumes it** (`SPEC.md §4a`: tool returns are the harness's, and the model meets results only as stored structure through `narrate`) *(consumer corrected 2026-08-28; the gate and this ID are unchanged)*.

## C. Status — latched acts over derived conditions

- **C1 [MUST]** — *Given* a 3-day OWD with waiver signed, deposit paid, deps intact, *when* the owner cancels it a week before, *then* `cancelled_at` is set and `status = cancelled` — it does **not** derive `active`→`completed` when the dates pass.
- **C2 [MUST / the un-expire bug]** — *Given* a hold with `expires_at 11:00` and unmet `{signature}`, *when* 11:00 passes (→ `expired_at` set, `status = expired`, unit read free) *and then* the signature lands at 11:30, *then* `status` stays `expired` — the late input does **not** un-expire it. `[ENGINE]` enforces the latch invariant; the harness must not model status such that the latch is derivable-away.
- **C3 [MUST]** — *Given* preconditions all met and start in the future, *when* the owner confirms, *then* `confirmed_at` is set and `status = confirmed` (the interval that had "no legal status" now has one).
- **C4 [MUST]** — *Given* a commitment with an unmet own-precondition AND an unmet dependency, *then* the derived layer can report both `pending` and `blocked` (coexistent), unless a latch overrides.
- **C5 [MUST]** — *Given* an event whose end has passed with no `actual_end`, *then* `completed` derives true automatically **for a non-completable kind** (FD-98, `SPEC.md §3.4`). *And the completable half:* a **completable** past its `end` with no tick derives **`review`**, never `completed`, and its `consumes` draw **stays consumed** until `actual_end` is recorded — the late return keeps the unit drawing, and nothing auto-completes it.
- **C6 [MUST]** — *Given* a bike due Sunday 17:00 returned **Saturday 10:00**, *when* `actual_end = Sat 10:00` is written, *then* it is stored (no `≥ scheduled end` rejection) and `completed = actual_end`. The unit frees at the actual return, not the scheduled one.
- **C7 [MUST]** — *Given* "boat must be back by Friday 17:00" (end role `terminal-constraint`), *then* it is **not** typed as an occupy-nothing task; the terminal constraint is honored and the boat is not booked out across Friday afternoon.
- **C8 [MUST / the clocked offer]** — *Given* a job offered to an instructor on Review with `expires_at` set from the offer's creator-set hold (§3.4; `../engine/SPEC.md §7.1`), *when* the window passes unanswered, *then* `expired_at` latches, the lapse fires the trigger loop, and the offer **cascades to the next ranked name**; *when* the first instructor taps "yes" late, *then* the offer stays `expired` — the late yes does not revive it (C2's invariant, applied to a person's answer).

- **C9 [MUST / the park cannot self-clear]** — *Given* a commitment parked by an unattended firing (D4/K2), *when* the loop fires again and the blocking condition now looks satisfiable, *then* the park stays set and the act does **not** retry — `needs_human.cleared_by` is written only by a human act, and the commitment is surfaced as parked regardless of what `status` derives to. `[ENGINE]` rejects an `engine`/`llm`-authored clear; the harness must not model the park as derivable-away (C2's discipline, applied to the park).

## D. The floor (M1 clarify/permission)

- **D1 [MUST]** — *Given* a tool that crosses the line (`send`) and no matching grant and no live confirmation, *when* the agent wants to call it, *then* it **asks** instead — it does not fire.
- **D2 [MUST]** — *Given* a stored grant `{action_class: notify, scope: this customer, unexpired}`, *when* the agent needs to notify that customer, *then* it fires **without** asking, and the act is recorded with `{who, basis: grant#, when}`.
- **D3 [MUST / never infer]** — *Given* no grant, *when* the agent has only an *inference* that the user would approve, *then* it still asks (silence ≠ consent; no inferred grants).
- **D4 [MUST / unattended]** — *Given* a trigger fires with no human at the console and the action needs a basis it lacks, *when* escalation finds no reachable human within the timeout, *then* the commitment is **parked** in a needs-human state and surfaced — no ungranted across-the-line act fires.
- **D5 [MUST / guest side]** — *Given* an off-app renter returns a form with a signature/payment, *then* their consent is taken from the form (not an agent), and the **owner's** agent still honors the floor when acting on the returned data.
- **D6 [MUST / attribution]** — every across-the-line act has `{who, basis, when}`; assert none can be found without it.
- **D7 [MUST / narrated, not composed]** — *Given* a standing grant covers an outbound message, *when* the message's factual content diverges from stored structure (the narrate spy detects free-composed facts), *then* the send is **blocked** before it fires — outward prose is `narrate(structure)` + the typed payload, never free model composition.
- **D8 [MUST / document-derived basis]** — *Given* a signed T&C that **names** a late-return fee, *when* the return comes in late, *then* the fee is **recorded** under the signature basis without a fresh ask; *given* a damage charge the document does **not** name, *then* there is no basis and the agent asks. Same commitment, same signature — the document's named terms are the scope.
- **D9 [MUST / destruction class empty]** — assert that **no tool in the contract declares the `destruction` reversibility class** (mirror of N2): cancellation is a latch and writes are diff-only, so nothing in the harness can destroy the sole record.
- **D10 [MUST / auto-accept is a Grant]** — *Given* an owner's setup answer *"accept bookings from my regulars,"* *then* a **Grant** is stored (`SPEC.md §7`) and every act it authorizes carries `basis: grant#` — assert that **no authorization path exists other than grant-or-live-confirmation**, structurally. A second mechanism would be a second place to look for who allowed an act.
- **D11 [MUST / auto-accept does not widen]** — *Given* that Grant, *when* a booking arrives from someone outside its scope, *then* there is no basis and the agent asks. Scope is matched, never inferred toward. *And the covered direction:* *given* a booking **inside** the Grant's scope, *then* it commits on the grant basis without a live confirmation, attributed `{who, basis: the Grant, when}` — assert both directions branch on the same covering relation (`SPEC.md §7`), so the test proves the matcher, not one of its answers.
- **D18 [MUST / confirmation is content-bound]** — *Given* the owner confirms an across-the-line act ("send Maria the 3 pm move"), *when* an argument changes before it fires (3 pm → 4 pm), *then* the changed act has **no basis** — the prior confirmation does not carry it — and the agent asks again. Assert `basis` records the confirmed tool + canonicalized args, so an approve-then-swap-args cannot read as authorized after the fact (`SPEC.md §7`, rules 2/4).
- **D19 [MUST / fail closed on an undeclared tool]** — *Given* a tool whose reversibility class is **undeclared or unclassifiable**, *when* the agent would call it, *then* it is treated as **across-the-line** — it asks, and never runs unattended on the guess that it was reversible. Assert the floor fails **closed**, never open (`SPEC.md §7` rule 5). The type-level impossibility of a missing declaration is M2's job (BUILD Step 2); this is the runtime backstop.
- **D20 [MUST / the floor property]** — the floor's invariant as a **property-based test** (`../TDD.md §Harness`): *no outward act ever occurs without a matching basis, under any tool-call sequence.* Over arbitrary interleavings of tool calls, confirmations, and grants, assert every across-the-line effect the spies recorded carries `{who, basis, when}` whose basis actually matches — a content-bound live confirmation (D18) or a scope-matched grant (D11). Names the harness's one property (the analogue of the engine's property-tested invariants); the executable test is written at build time. **The generated constructor roster's single source is `SPEC.md §5`'s printed roster** (reached through §3.11's roster of record): the arbitrary's constructors, §5's tool rows and the outward-act predicate's range are **one set**, keyed by the roster's stable identifiers — three lists quietly diverging is the defect this sentence exists to prevent. **Home: `SPEC.md §7`** — no new law.
- **D24 [MUST / a Grant is minted only on a live confirmation]** — *Given* an elicitation whose answer routes to a Grant (G1), *then* the mint fires only on a **live, content-bound owner confirmation at the console** (`SPEC.md §7`, FD-24) — the stored `action_class` and `scope` are exactly what the confirmation displayed, and the mint is attributed to it. *Given* a proposed Grant the owner does not confirm, *then* nothing is stored. Assert the `authorization` class is declared at the tool boundary like every other class (D19's discipline covers it if undeclared). **And the class has its named carrier:** the mint/widen/narrow/revoke acts land on the `grant.give` / `grant.revoke` roster row (`SPEC.md §5.2`) — assert the class occupies that row rather than floating carrier-less.
- **D25 [MUST / no unattended or external mint]** — *Given* `grant.give` normalized from a trigger firing, or arriving through the external surface (`SPEC.md §5.3`), *then* it is **refused** — not queued, not parked for later approval as if it were the owner's own proposal. Assert the refusal both ways, and assert a Grant is **never the basis for minting or widening a Grant** on the `grant.give`/tool-boundary path — the authorization class has no grant-shaped basis at all there. *(Scoped 2026-08-22: the engine-minted `ShareGrant` on §7.1's stored-accept path is FD-32's one ruled carve — the application of a Grant the owner already minted, outside this row's path and untested here.)*
- **D26 [MUST / an injection cannot mint its basis]** — *Given* assembled context containing a non-owner string that induces the model to emit `grant.give` (the L5 fixture corpus supplies the string), *then* no Grant is stored and no outward act later fires on any grant that did not exist before the firing — asserted over the whole firing, which is what makes `../security/SPEC.md §5`'s "an injection could only propose" true for authorizations. Extend D20's generated input space with `grant.give` events so the property covers the mint path, not only the spend path.
- **D27 [MUST / no signed term, no guest-facing debt]** — *Given* a closed rental whose signed checklist names **no** damage fee, *when* the owner says "charge him for the damage," *then* **the utterance is refused and no record stores** — no `owed` derives against the guest, no outward claim fires, and **no internal `priced` record stores either**: the SPEC-tier story's beat is a refusal with the ask, not a bookkeeping fallback (`../user-stories/Situations/Situation-B/situation-3.md` governs; the prior mapping let an ordinary internal mark stand in for the refusal). Assert the outward spy recorded zero sends, the guest-visible money state is unchanged, **and the store holds no money record from the utterance**. **D8's context, in one sentence:** D8 permits recording a charge the signed document **names** — a live confirmation atop a named, stored term; this scenario is the negative space where the document names nothing, and no confirmation substitutes for the missing term. *(Situation-B's must-be-refused beat, `situation-3.md` — previously mapped to D8, which permits exactly this charge on a live confirmation; the story's refusal is about the guest-facing claim, and this scenario pins that distinction.)*

- **F1 [MUST]** — *Given* a new rule that contradicts a **governing** rule, *then* the write is a **hard stop** (only forward move is a recorded exception).
- **F2 [MUST]** — *Given* a new rule that contradicts the owner's **own** rule, *then* the agent surfaces both and requires an explicit **override stored with a reason**.
- **F3 [MUST]** — *Given* two rules that don't clash yet but could, *then* the agent **alerts, does not block** (latent inconsistency).
- **F3b [MUST / unsatisfiable is not overridable]** — *Given* two of the owner's **own** rules that are jointly unsatisfiable (a boat minimum above its capacity; a minimum duration longer than any allowed window — `../engine/SPEC.md §8` item 4), *then* the agent **does not offer the F2 override path**: it surfaces the refusal with both operands and the remedy, and the write does not land. Assert the override affordance is **absent**, not merely unused — an owner who can override here ends up with rules that look stored and can never place anything.
- **F4 [MUST]** — *Given* a completed course validated under governing version N, *when* the governing standard is revised to N+1, *then* the completed course keeps its `effective`/version-of-record stamp and is **not** flipped to non-compliant.
- **F5 [MUST / own terms forward-only]** — *Given* booked lessons at NT$100/hour, *when* the owner raises the rate to NT$120 (or reshapes a course), *then* the already-booked commitments **keep the terms they were made under** and the change applies only to bookings made from then on. No live commitment is silently re-priced by a later edit.
- **F6 [MUST / in-flight machine states keep their operands] `[ENGINE]`** — *Given* a unit mid-cooldown under a six-hour buffer and a live hold mid-clock, *when* the owner edits the buffer to three hours and the hold window shorter, *then* **the running cooldown finishes the six it entered with and the live hold keeps its clock** — the edits govern placements and holds created afterward, never a window already running (`../engine/SPEC.md §1.5` — `hold` binds at booking; a placement's gap requirement binds at its own commit). Assert both directions: a new booking after the running window closes uses the new operands. *(Situation-B's in-flight beat, stated twice in the story and previously covered nowhere; the enforcement is engine-side, the harness surfaces it.)*

## K. Loop verification (check-work)

- **K1 [MUST / bounded, attended]** — *Given* a turn whose commit produced stored structure that diverges from the normalized intent (stub returns a mismatched state on every read), *then* the agent detects the mismatch via read-back and does not terminate claiming success; it re-enters the loop **exactly once** and then surfaces the mismatch to the owner as a gap. Assert across the whole turn, **over the enumerated work-commit family** (`SPEC.md §3.14`'s two-write-families law — domain-structure writes and basis-spending commits; loop bookkeeping is excluded by name, the `FiringEvent` parts included) *(counted class named 2026-08-28)*: **at most two work commits, of which at most one spends a basis**, and **exactly one outward send** — the re-entry re-commits stored structure but never spends a second basis or re-fires an act already attributed (`SPEC.md §7`'s spend-vs-delivery-evidence split, which is also how this count composes with X4's one-commit-point constraint: the commit point is the basis-spending commit). **And assert the birth co-write is present in the generated sequences** — the record's birth rides the first work commit's payload under that commit's own write id and does **not** raise the count.
- **K2 [MUST / unattended]** — *Given* a trigger firing with no human present whose effect fails verification against the engine re-read, *then* the firing does not finish silently — it **parks** the commitment in a needs-human state (consistent with D4). Completion is never claimed unverified.
- **K3 [MUST / the loop terminates, and nothing escalates]** — *Given* a **trigger** firing whose engine re-read mismatches on every attempt, *then* the firing terminates in bounded attempts and **parks** the commitment. Assert the absences: **no act was re-fired** (the outward stub recorded exactly one call), and **no Escalation object was created** — a verification mismatch has no route to the ladder, because the ladder answers a missing basis and nothing here is missing a basis (`SPEC.md §3.9`).
- **K4 [MUST / a lost response cannot duplicate]** — *Given* a `commit` whose write applied but whose **response was lost** (the stub's `timeout` fixture: applied, no reply), *then* check-work's one retry re-commits **the same write id** (`INTERFACES.md §1.2`) and receives the original result — assert the store holds **exactly one** commitment, never two, and K1's at-most-two-commits count is unchanged. *Given* a genuine `unavailable` (nothing applied), *then* attended the turn surfaces a gap and unattended the firing **parks** — an infrastructure failure is never read as a semantic conflict, and never silently retried past the one bounded retry.

### The firing record (`SPEC.md §3.14`) — five rows added 2026-08-28

- **K5 [MUST / a completing turn lands one record, in two parts]** — *Given* a turn that completes and verifies, *then* its `FiringEvent` **birth** lands **inside the firing's first work commit**, bundled under that commit's own caller-supplied write id, and its **seal** — carrying `termination: completed-verified` — lands **after check-work** as its own standalone bookkeeping write under the derived `seal_write_id`. Assert **exactly one record for the firing id**, both parts present, neither mutated; assert the firing's assembled context is **re-derivable from the birth's assembly reference plus the store** (L2's determinism, now against a stored reference rather than a live re-run); and assert **neither part raised K1's work-commit count**.
- **K6 [MUST / re-entry cannot mint a second birth]** — *Given* K1's mismatch fixture, so the turn re-enters **exactly once** under the same firing id, *then* there is **one** record: the birth bundled with the firing's **first** work commit **only**, and the re-entered turn bundles no second birth. Assert the absence structurally, not by count alone: a wrongly re-bundled birth carrying an **identical** payload is **inert** (§6's idempotency returns the original result) and one carrying a **different** payload is **refused whole** (`{conflict, reason: write-id-reuse}`, the whole bundle rejected) under the (firing id, part) part-identity law — **a second birth is never representable**. The seal carries the turn's final outcome per the lifecycle.
- **K7 [MUST / a post-commit park seals on the park's own write]** — *Given* a firing that makes a work commit and then parks (`needs_human`, K2's shape), *then* the birth rode the work commit and the **seal rides the `needs_human` write** — co-written inside it, bundled under that write's id — carrying `termination: park`. Assert no third write appeared for the record, and that the park write is **not** counted by K1/X4 (it is loop bookkeeping, excluded by name, `SPEC.md §3.14`).
- **K8 [MUST / required-on-read fails closed, and an absent seal is not that case]** — *Given* a stored `FiringEvent` carrying a member the reader does not know, *then* the read **refuses whole** — a structured error, **never a partial read and never a skip**. Assert the absence of any partial-read path. *And the negative half:* an **absent seal** is **not** this case — a birth with no seal reads as the defined `interrupted` state, derived from the seal's absence and **never stored as a member**; assert it surfaces rather than erroring, and that no `interrupted` value is found anywhere in the store.
- **K9 [MUST / the residual path lands late, keyed and independently retryable]** — *Given* a firing whose engine seam is **unwritable at termination** (`unavailable`/`timeout`, `INTERFACES.md §1`'s infrastructure members) so its record is held as process-local state, *when* the engine becomes writable, *then* the record lands **late**, keyed to the **same firing id**, with **each part as its own standalone call under its own derived write id**. Assert **independent per-part retry**: a retried part repeats idempotently on its own id while the other part's presence or absence is undisturbed. Assert **both** the firing time and the engine-attributed arrival time are recorded, so lateness is visible; and assert K1's count law is **undisturbed** — the late landings are bookkeeping, not work commits. *(The printed ceiling this row cannot test: a process death before the engine returns loses the unsealed content — detectable on read as `interrupted`, K8's half.)*
- **K10 [MUST / the co-write is a lawful seam input]** — *Given* a birth (or seal) bundled into a host work commit per `SPEC.md §3.14`, *then* the bundle rides the host commit's **closed input forms** under the host's **one** caller-supplied write id (`../engine/SPEC.md §6`'s one-id-covers-the-bundle shape) — no second input form, no second id, no widened `commit` signature (`INTERFACES.md §1.2` unchanged). Assert at the seam: the stub accepts the bundled payload as one commit call; a bundle whose part conflicts with its (firing id, part) slot is **refused whole**; and the engine-side admission sentence is the engine's law (`../engine/SPEC.md §6`), consumed here, never restated.
- **K11 [MUST / the ceiling park says budget]** — *Given* a firing that reaches its declared step-and-spend ceiling (`SPEC.md §4`'s fourth termination — **steps** as routed tool calls, **spend** as basis-spending acts, §4a's counted classes), *then* the firing **parks** rather than erroring or running on — no further step or spend occurs past the ceiling (the outward stub records nothing beyond it) — and the commitment enters `needs_human` with `reason: budget_exhausted` carrying `{ kind: budget-ceiling, ceiling, spent }` (`SPEC.md §3.4` — the parked card names the budget as the reason, with `ceiling` and `spent` as counted); asserted once, unattended, on the virtual clock; the park then obeys C9's no-self-clear law (reused, never restated).

## R. Turn flow — the step machinery (`SPEC.md §4a`)

*Added 2026-08-28 with §4a. - **R1 [MUST / dispatch is deterministic]** — *Given* the same `normalize` output replayed against the same store state, *then* the harness routes the **identical tool sequence** both times — same tools, same order, same arguments — from the routing tables alone (L2's determinism discipline moved down to the dispatch layer). Assert the sequence is a function of `{intent, store state}` and of nothing else; assert in particular that it does **not** vary with anything the model returned beyond the intent and its fields.
- **R2 [MUST / no model-chosen call]** — assert the affordance is **absent**, not merely unused (the D9/N2 absence style): **no model output can select, add, reorder or skip a tool call.** *Given* a scripted model return that attempts it — naming a tool, requesting a sequence, or claiming a next step — *then* it is **inert data**: the routed sequence is unchanged and the attempt is recorded rather than obeyed. *And assert the seam is not widened:* the model seam carries **exactly four call types** and no `tool_schemas` member reaches any assembled context — the model is never shown the `SPEC.md §5` tool surface (`INTERFACES.md §2`, the four-call pin; §4a).
- **R3 [MUST / per-owner serialization closes the read-staleness hole]** — *Given* one owner and a firing in flight, *when* a second trigger lands during it, *then* the second firing **queues** and its slice is assembled **after** it claims — so it sees the first firing's commits, never a store state the first has already moved. Assert on the virtual clock, and assert **all six trigger sources and console turns queue identically** — no wake-priority ordering exists to test around (§4a; the engine's commit-time arbitration is a different wall, `INTERFACES.md §1.2`). **The six-source claim runs from six declared fixtures, one per source** (sale, hold-expiry, decline, returned-form, clock, delivery-report): a source with no fixture is a hole this row turns red on, never a silent narrowing.
- **R4 [MUST / completion is proposed by the sequence, verified by check-work]** — *Given* a routed sequence in which every step has executed or been **refused with a disposition**, *then* that completion is what enters **check-work** (§4), which verifies it before the firing terminates. *And the negative half:* an **unfinished** sequence — a step neither executed nor dispositioned — **never claims done**: assert the firing does not terminate as `completed-verified`, and that no model output can make it (K2's "completion is never claimed unverified", now with the thing being claimed defined).
- **R5 [MUST / the compound utterance — independent steps proceed, dependents take `refused-unmet`]** — *Given* a compound utterance normalized to `normalize`'s ordered-sequence branch (`INTERFACES.md §2.1`) in which one step is refused at the floor, *then* every step **independent** of the refused one executes normally — **no global halt** — and every step **dependent** on it takes the internal disposition **`refused-unmet`**, stored and reported at the routing layer, deliberately **not** a seam refusal reason (`INTERFACES.md §7.1`'s closed table unchanged — assert no such reason string crossed the seam). The sequence terminates through R4's law: every step executed or dispositioned, check-work verifies, and an unfinished sequence never claims done (`SPEC.md §4a`, part of FD-86).
- **R6 [MUST / a pre-birth claim death re-enters FIFO and leaves a visible loss record]** — *Given* a firing claimed from the engine-stored inbox that dies **before its record's birth** (no work commit, no birth part), *then* the claim **releases back to the inbox** and the trigger is re-attempted in FIFO order, **and an owner-visible loss record is written** — attributed, surfaced like any gap (FD-96, `SPEC.md §4a`). *Assert both arms, and the failure of each alone:* re-attempt with **no** record is a silent retry loop — assert the record exists; a record with **no** re-attempt drops a trigger the corpus promised would fire — assert the re-claimed firing runs. Post-birth death is K8's ground: the absent seal reads `interrupted`, and this row never fires on it.

## L. Context assembly

- **L1 [MUST / self-sufficient firing]** — *Given* a trigger fires with no conversation (a hold expiry at 03:00), *then* the assembled context contains the **handoff frame** — the trigger event, the affected commitment's stored structure, and the covering rules/stored answers — and the firing completes (or parks) without needing any conversational history.

## O. The assisted off-app path (`SPEC.md §2` — *"assisted, recorded, and converted"*)

*The edges the network cannot reach. `SPEC.md §2` has always specified this — the agent prepares the owner's phone call, records the answer as ordinary internal writes, and offers a floor-gated invite — and until now no BUILD step claimed it, so a specified capability had no build home. These scenarios pin it. Drawn from `../user-stories/Situations/Situation-C/situation-5.md`, the minimal-adoption world: the four unavoidable calls, prepared and recorded, each becoming an invite. **Every scenario below composes existing machinery — no new tool, no new seam verb, no new trigger source, no second authorization path.** If satisfying one of these tempts a new atom, that is the finding, not the fix.*

- **O1 [MUST / the call is prepared, never placed]** — *Given* an outward need whose counterparty is off-app and unreachable by any channel the app can send on, *when* the agent handles it, *then* it assembles a **preparation for the owner** — who to call, what to ask, and which stored fields the answer will land in — and **fires nothing outward**: no `send`, no third-party contact of any kind. Assert the app spy recorded **zero** outward acts for the firing, and that the preparation's facts are `narrate(structure)` over stored data, never free-composed (D7). The owner places the call; the harness never does.
- **O2 [MUST / the answer returns as ordinary internal writes]** — *Given* the owner comes back from that call with an answer, *when* it is recorded, *then* it lands through the **existing** write path — diffs via `CRUD_*` under the floor, attributed `{who, basis, when}` where the basis is the owner's own act — and classifies **internal**: the owner reporting what a human told them moves nothing outward and crosses no line (N1's shape). Assert **no tool outside the `SPEC.md §5` contract was called**, and that the resulting store state is indistinguishable from the same fact arriving through any other door **except provenance, which stays honest** *(corrected 2026-08-21 — the prior "indistinguishable" contradicted L4)*: the *act* is the owner's and attributes to them, but the answer's **free text is a third party's words** and is never tagged `owner` — it is not countable by the noticed-pattern detector, exactly as a `guest` string is not (L8). A relayed stranger is still a stranger.
- **O3 [MUST / the invite is an ordinary across-the-line act]** — *Given* a prepared call whose party is not on annnä, *when* the agent offers to invite them, *then* the invite is **across the line** and needs a live confirmation or a matching `Grant` exactly like any other outward act (D1), attributed (D6). Assert that having just spoken to someone **creates no basis to message them** — the call is not consent — and that a declined offer sends nothing and **stores the decline as a small owner-and-party record** (declined/revocable, persisted through the existing `commit` verb — the `SPEC.md §3.10` precedent: a fact about the owner-and-party pair fits none of the five routing shapes, so it gets its own stored shape, the builder's design work at `BUILD.md` Step 7) rather than re-offering on the next firing for the same party.
- **O4 [MUST / no contact without a basis, over the whole path]** — assert the assisted path adds **no new way to reach a real person**: the preparation is owner-facing (O1), the answer is owner-supplied (O2), and the invite is the single outward act and is floor-gated (O3). Therefore the floor property (D20) covers this flow **unextended** — run D20's property-based test over sequences that include assisted-call firings and assert it still holds with no new case added to it. A path needing its own floor rule would mean the floor was never a property.
- **O5 [MUST / a silent off-app party lapses, it never blocks]** — *Given* a clocked offer to a party reachable only by an assisted call, *when* no answer is recorded before the offer expires, *then* it **lapses on the virtual clock and cascades exactly as C8 specifies** for any other offer. Assert the assisted path introduces **no special waiting state, no second expiry mechanism, and no indefinite park** — an off-app counterparty's silence is ordinary silence, and Situation C's clocked offer past a silent freelancer is this scenario.
