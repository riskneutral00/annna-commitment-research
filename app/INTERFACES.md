## §4. Stub strategy — from spies to the real thing

The harness suite runs against app stubs that are **record-and-return spies** (`../harness/INTERFACES.md §5`): they assert the payload and reversibility class, and simulate `on_form_return`. Swap-parity means the real app preserves exactly the **contract-visible** behavior the spies asserted:

- `render`/`render_generative`: the real app accepts every payload the spies accepted and rejects what they rejected (unknown node types) — the visual output is new, the contract behavior identical.
- `publish`: real token URLs replace canned artifacts; blindness and attribution properties hold on real responses.
- `send`/`on_form_return`: real email/hand-over replaces the spy's simulation; returns still fire the loop with token attribution.

The app's own `SCENARIOS.md` runs headless where possible (payload/wire assertions) and drives the rendered canvas only where the scenario is about the canvas itself. The internal account-document adapter uses an account/revision-aware document-store double with controllable concurrent writes, dependency insertion and dropped acknowledgements. V2 checks the real app controller against that double without canvas rendering; the same authenticated path and store contract are exercised on the existing backend at BUILD Steps 7/8. A render spy is not proof of persistence. C5/V1 also use a scoped PartyContact read double with two owners, a guest credential, existing/new identities, same-name strangers and controllable lost/stale responses under `../harness/SPEC.md §3.12`; real engine keyed read/write and reference/replay behavior remain engine BUILD Steps 1/4/5, with app parity at its existing swap.

The **marketplace service stub** is a canned catalog + entitlement map (`../marketplace/INTERFACES.md §5`); appearance scenarios S6/S7 run against it both present and absent. **The send-substrate stubs cover the whole `SPEC.md §6` roster** *(2026-08-31, F-30)*: the email, LINE and WhatsApp substrates are each a scripted send-or-hand-over spy returning the recorded outcome — three mocks, one seam shape, so D8's template-honest send and the hand-over path run without any live provider.
