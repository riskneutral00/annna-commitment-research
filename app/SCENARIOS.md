## U — Generative-UI discipline
- **U1 [compose]** A valid schema of catalog nodes renders the composed view; every node maps to a manifest component. For `SPEC.md` §§1/4.1’s field lifecycle payload, render current type, required/optional state, default/use scope and independent-removal success; render a referenced-removal candidate with concrete dependencies and supplied valid keep/rebind/dependent-rule choices. - **U2 [reject unknown]** A schema containing one unknown node type: structured error returned to the harness, **nothing rendered for that schema** — no partial view, no guessed widget. Under `SPEC.md §4.1`, a `file-slot` schema from a draft, saved document or catalog is rejected whole with no fallback FileInput/attachment control. A valid structured-field/signature schema remains renderable.
- **U3 [generate-once]** The same stored schema rendered twice produces identical output with **zero model calls** (asserted by instrumentation: the render path has no model client to call).
- **U4 [data not code]** A schema attempting executable content (script node, event-handler string) is unrepresentable in the meta-schema — it fails validation before rendering is ever attempted.
- **U5 [unknown prop = rejected render]** A schema whose node carries a prop outside that type's closed manifest prop list (`SPEC.md §4.1`): structured error, nothing rendered for that schema — U2's poka-yoke, props half. *(Added 2026-08-21 — the props rule was a MUST with no defining artifact and no test; the manifest now carries per-type prop lists.)* For `SPEC.md §4.1` and harness §3.3, also reject binding by label/index, a missing or retired slot in the selected revision, incompatible node type/default and an invented deletion/formula prop. Accept the same slot in its retained historical bound schema; a current retirement does not make the old form unreadable. No rejected schema emits a write or retargets a fallback row.
