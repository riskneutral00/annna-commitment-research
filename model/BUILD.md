## Step 0 — Eval scaffold
- Stand up the exam runner: load an EVALS set, call `complete()` through the provider seam, grade (exact-match + rubric), report per-set scores against thresholds. **The prompt assets this runner exercises are provisional at this step** *(2026-08-31, F-11)*: Step 2 is where all three production assets are authored; a Step-0 run against provisional assets calibrates the scaffold, never the model.
- **Two kinds of asset are created here, and only one of them is provisional** *(2026-09-13 — `INTERFACES.md §3` assigned every prompt asset to the step that first needs it and named Step 2, while this step already exercises assets and `EVALS.md §1` already says the judge prompt is authored with the scaffold; the same file had two producers depending on which home a builder opened)*. **The provisional call assets are this step's** — stand-ins the scaffold is calibrated against, replaced wholesale by Step 2's production assets. **The judge/grader asset is this step's too, and it is frozen here**, on `EVALS.md §1`'s lifecycle — authored with the scaffold, re-frozen only with the exam itself, never re-authored at Step 2. Where either lives and what a version of one is stays `INTERFACES.md §3`'s: `model/prompts/`, the asset's content hash as its version.
- Seed with the EVALS §2 **text sets** as they stand — **including the S-set**, whose two modes (carry-through, loss) are scored separately from the start; a scaffold that reports one S number has already lost the loss trap. **The P-set is not seeded here** *(2026-08-21)*: it grades stored engine state after a real turn, and this scaffold has no turn execution, no engine, and no fault injection — P joins at Step 3 (EVALS §2's P section states the deferral).
- **The DR-7 spike is gone** *(deleted unrun 2026-09-17, FD-109, ahead of this scaffold; DR-7 closed)*: this runner is the N-set's only home. When it can run keyed, its record mode lands its own `../deployment/egress-allowlist.md` row and `../deployment/env-manifest.md` rows first, as their own spec commit; keyless replay makes no egress call and needs no row.
- **Snapshot custody — how a recorded firing is made, stored and replayed** *(authored 2026-08-29; part of FD-84 (Drafted 2026-08-28, not ratified — pending FD-84) — the replay invariant at `../harness/SPEC.md §3.14` is what this mechanism serves)*. This is the mechanism's home; every other site cites it. Without it the exam can never gate in CI, which is the one place a reproducibility claim has to hold for somebody other than its author.
  - **Replay is the default, and it is what CI runs — keyless.** The scaffold loads recorded firings from the tree and grades them. No provider key is present in that lane, so a replay run cannot spend and cannot reach a network.
  - **Re-recording is a separate, deliberate, keyed command** — never a fallback the runner takes on its own when a recording is missing. Its workflow declares the protected environment the model-key lint requires (`../deployment/env-manifest.md`'s `OPENROUTER_API_KEY` row: in CI that key exists only in the protected qualification environment). **Neither that workflow nor that environment exists yet**, which is why re-recording is not runnable in CI today.
  - **A recording is normalized to a fixed point.** Volatile identifiers — ids, timestamps, request handles — are replaced by **typed tokens that preserve the relationships between them**, so the same firing recorded twice is byte-identical while a firing that genuinely changed still reads as changed. What normalization must **not** do is redact ordinary text because it resembles an identifier: a summary that mentions a booking number is graded text, and blanking it destroys the item.
  - **What identifies a recording is the whole call input and the binding that ran it** *(2026-09-13 — `INTERFACES.md §2.1`'s replay identity; the custody rules were silent on the key, and the composition recipe they sat beside named only the context)*: the call's prompt asset hash, that call's arguments (`utterance` and the assembled context, or the `structure`, or the `raw_text` and its `source_tag`) and the qualified `provider`/`model_id` beside them. A lookup keyed on the context alone hands one recording to two different utterances, which is the confusion the identity is stated against. A call whose input or binding differs **misses**, and a miss refuses per the verify below rather than calling out.
  - **The qualified binding in that identity also carries its sampling values**: `temperature` and optional `reasoning_effort`, alongside `provider`, `model_id` and the prompt asset hash. The existing Step 2 provider-contract suite must retain the sampling-only counterexample — identical call inputs with only `temperature` or `reasoning_effort` changed are a different identity and must miss.
  - **Secrets are structurally absent rather than scrubbed.** A recording is the graded exchange — `messages` in, structured return or error-union member out (`INTERFACES.md §2.1`) — and not the HTTP transport, so there is no header, key or bearer token in the artifact for a scrubber to miss.
- **Blocked on** *(conditions, not an order of work — 2026-08-29; a builder previously hit each of these one at a time with nothing written down)*:
  - **a provider account and key existing** — the founder's act (SPEC §7's G2-2 note; `../deployment/env-manifest.md`'s `OPENROUTER_API_KEY` row). Snapshot custody does not remove this: replay needs **one keyed recording session** to mint the recordings it then replays keylessly forever.
  - **the keyed lane's protected CI environment, and a workflow declaring it** — **neither exists**; they are named here as absent, not cited as files. Until they do, the keyed record mode cannot run in CI and every qualification claim is a local artifact nobody else can reproduce.
  - **a judge identity** — the `judge` block (`INTERFACES.md §2.2`) filled in, and its obligations met (`EVALS.md §1`): the rubric half of "grade (exact-match + rubric)" needs a judge binding, a frozen prompt, and a home for the record of which languages it may grade.
  - **the coverage conditions stated rather than silently thin** (`EVALS.md §2`'s N-set and S-set preambles) — which is what makes it lawful to start here with seed-size sets.
- **Verify — reported as two halves, because they close on different conditions** *(2026-09-13 — the line was one keyed run and a deletion, so a scaffold that reported one S number, plumbed no rubric, silently re-called on a missing recording and replayed non-deterministically could satisfy it whole, and a builder had no way to report the half that closes without the founder's account)*:
  - **The local half — keyless, scripted, and it closes here.** Against scripted provider fixtures the runner: loads **each seeded EVALS §2 text set** and reports its per-set score against its threshold (§1's minimum-n rule holds, so at seed size every bar is reported as perfection); reports the **S-set's two modes as two separate scores** — carry-through and loss — with no path that collapses them into one number; carries a rubric item end to end through the judge binding and its prompt hash into the scorecard, **the plumbing only**; **refuses on a missing recording**, rather than falling back to a live call, and makes no egress doing so; **replays deterministically** — the same recorded firing graded twice produces the same bytes; and normalizes, stores and reloads a recording under the snapshot-custody rules above. **All of it is scaffold evidence and is reported as such**: scripted fixtures prove this runner's mechanics and never a model's quality, and no scripted run produces a qualification record (`EVALS.md §3` owns what one is).
  - **The rest of the step — the existing obligations, unchanged and still owed.** As before, the scaffold runs the N-set against any one OpenRouter model and produces a scorecard; that run needs the **one keyed recording session** and the live-registry check on the slug it runs (the condition Step 3's roster bullet places here), and the rubric half needs the **actual** judge binding and frozen prompt with `EVALS.md §1`'s human pass over every judge-graded fail and its sample of passes. The local half discharges none of these. And the spike directory no longer exists.

## Guardrails
- **The exam gates everything:** no model, prompt, or routing change goes live unqualified (EVALS §3).
- **No prompt smuggling:** if a prompt starts encoding policy (scopes, floors, prices), stop — that belongs in the harness/engine, and the exam's J-set should have caught it.
- **Scope:** anything deterministic you're tempted to build here is the harness's or engine's; this layer owns only vocabulary, prompts, routing, and the exam.
